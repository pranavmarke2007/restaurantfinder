4. Algorithms & Mathematical Techniques

4.1 Haversine Formula — GPS Distance Calculation

Purpose: Calculate the straight-line (great-circle) distance between two GPS coordinates on Earth's surface.

Used in: calculateDistanceKm(lat1, lon1, lat2, lon2) in script.js

Formula:

a = sin²(Δlat/2) + cos(lat1) × cos(lat2) × sin²(Δlon/2)

distance = 2 × R × atan2(√a, √(1−a))

Where R = 6371 km (Earth's mean radius), Δlat and Δlon are converted to radians.

Reference: Wikipedia — Haversine formula

4.2 Weighted Multi-Criteria Scoring Algorithm

Purpose: Score each restaurant (0–100) against user preferences using multiple weighted criteria.

Used in: calculateRestaurantScore() in script.js

CriteriaMax PointsMethod
Cuisine Match40Weighted preference list matching against restaurant text
Dish Match30Weighted preference list matching against restaurant text
Favorite Restaurant Similarity20Exact name match (20pts), word overlap (10pts), cuisine overlap (10pts)
Semantic Taste Profile10Set-based word overlap between restaurant text and taste signature

Total = min(100, cuisine + dish + favorite + semantic)

4.3 Set-Based Text Similarity (Jaccard-like)

Purpose: Measure semantic similarity between restaurant attributes and user's taste profile.

Used in: calculateTextSimilarity(sourceText, targetText) in script.js

Method:

  1. Normalize both texts (lowercase, remove special chars)
  2. Tokenize into words, filter words ≤ 2 characters
  3. Convert each to a Set of unique words
  4. Count how many target words exist in source set
  5. Similarity = matches / targetWords.size

Reference: Inspired by Jaccard Index / Jaccard Similarity Coefficient

4.4 Min-Max Normalization for Hybrid Sorting

Purpose: Combine match score (0–100) and distance into a single composite ranking score.

Used in: sortRestaurants() in script.js (hybrid mode)

Method:

normalizedDistance = (distance / maxDistance) × 100

compositeScore = (matchScore × 0.6) + ((100 − normalizedDistance) × 0.4)

Weights: 60% match quality, 40% proximity

4.5 Multi-Provider Fallback Chain

Purpose: Ensure geocoding always succeeds by trying multiple providers sequentially.

Used in: getCoordinatesFromLocation() in script.js

Chain: Open-Meteo → Photon/Komoot → Nominatim

If one provider fails or returns no results, the next is tried automatically.

4.6 Image Resolution Priority Chain

Purpose: Find the best available image for each restaurant through cascading fallbacks.

Priority:

  1. Direct image tag from OSM data (tags.image)
  2. Wikimedia Commons file tag from OSM (tags.wikimedia_commons)
  3. Wikimedia Commons search API (by restaurant name + city)
  4. Placeholder image from placehold.co
